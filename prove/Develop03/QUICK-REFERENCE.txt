💡 KEY TALKING POINTS
─────────────────────────────────────────────────────────────────────────────

"Why three classes?"
→ Each class has one job. Word tracks visibility, Reference stores location,
  Scripture manages the game. This makes code clean and easy to maintain.

"Why getters and setters?"
→ They keep each class's data safe. Other code calls Hide() instead of
  directly changing _isHidden. This way Word controls its own state.

"Why does Scripture constructor take text as a string?"
→ It splits the text into Word objects internally. This way the main program
  doesn't need to know how Scripture stores its data.

"How do the classes work together?"
→ Scripture creates Word objects from verse text. It calls Hide() on random
  Words. When displaying, it asks each Word what to show. When checking if
  complete, it checks each Word's hidden status.
